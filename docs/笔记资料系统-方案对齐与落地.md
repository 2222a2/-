## 0. 原方案与项目的核心冲突（已修正）

| 冲突点 | 原方案说法 | 项目真实现状 | 对齐决策 |
|---|---|---|---|
| 正文存储 | 新增 `rich_body TEXT` 存 HTML，不提现有 `content` | 现有列是 `content TEXT`，FTS 索引的就是它 | **保留 `content` 作 FTS 真源（纯文本）**，新增 `rich_body` 存 HTML；入库时两者同步 |
| 文件指针 | 新增 `file_ref` 指向已上传文件 | M0 上传已把文件指针存在 `source_id`（文件名）和 `url`（路径） | **砍掉 `file_ref`，复用 `source_id`**；新增 `url` 列专供网站型 |
| 接口命名 | 全新 `/api/notes`、`/api/notes/packages` | 现有聚合底座是 `/api/knowledge`（前端 `client.ts` 已对接） | **沿用 `/api/knowledge` 前缀扩展**，不另起路由（符合"能复用一律复用"） |
| 净化依赖 | 后端 `nh3` 净化 | `requirements.txt` 未声明、`.venv` 未装 | 已装 `nh3==0.3.7` 并写入 `requirements.txt` |
| 富文本编辑器 | 前端 TipTap | `package.json` 无 tiptap（仅有 OnlyOffice） | 已装 `@tiptap/react` + `@tiptap/starter-kit`（OnlyOffice 仍只用于 .docx/.xlsx 文档编辑，二者职责不同） |
| 拼音分组 | "中文按拼音首字母分组" | SQLite `ORDER BY` 默认按 Unicode 码点，≠ 拼音 | 新增 `title_pinyin` 列（pypinyin 生成），`ORDER BY title_pinyin` 真正按拼音 |
| 时间筛选 | "后端算今天/本周/本月避开时区坑" | `created_at` 用 `datetime('now')` 存的是 **UTC** | 区间也按 **UTC** 计算，格式 `'%Y-%m-%d %H:%M:%S'` 与存储一致，端到端统一 |
| `task_doc` 映射 | `task_doc→file/note`（未定） | 旧 `source_type` 含 `task_doc` | **明确 `task_doc→file`**（任务产出文档按文件型归档） |

## 1. 数据库 Schema（最终）

### 1.1 `knowledge_card`（扩展，幂等 ALTER）
```sql
-- 在原有 id/title/content/source_type/source_id/created_at 基础上新增：
ALTER TABLE knowledge_card ADD COLUMN item_type TEXT;        -- note | website | file（统一筛选维度）
ALTER TABLE knowledge_card ADD COLUMN package_id INTEGER
    REFERENCES note_package(id) ON DELETE SET NULL;          -- 归属包，NULL=未归档
ALTER TABLE knowledge_card ADD COLUMN url TEXT;              -- 网站型跳转地址
ALTER TABLE knowledge_card ADD COLUMN rich_body TEXT;        -- 富文本 HTML（笔记用）
ALTER TABLE knowledge_card ADD COLUMN title_pinyin TEXT;     -- 标题拼音，用于按拼音排序/分组

CREATE INDEX IF NOT EXISTS idx_card_package   ON knowledge_card(package_id);
CREATE INDEX IF NOT EXISTS idx_card_itemtype  ON knowledge_card(item_type);
CREATE INDEX IF NOT EXISTS idx_card_created   ON knowledge_card(created_at);
```

**字段职责边界（关键）**
- `content`：**纯文本**，永远是搜索（FTS5）与降级展示的真源。
- `rich_body`：**HTML**，仅用于富文本笔记的所见即所得展示；为 NULL 时前端回退渲染 `content`。
- `source_type`：资料**从哪来**（`web_clip|upload|task_doc|note`），M0 既有语义，保留。
- `item_type`：资料**是什么**（`note|website|file`），新筛选维度，与 `source_type` 解耦。
- `source_id`：文件指针（M0 已存文件名），**不再新增 `file_ref`**。

### 1.2 新表 `note_package`（包 / 文件夹）
```sql
CREATE TABLE IF NOT EXISTS note_package (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    name        TEXT NOT NULL,
    parent_id   INTEGER REFERENCES note_package(id) ON DELETE SET NULL,  -- 自引用，NULL=顶层
    sort_order  INTEGER DEFAULT 0,
    color       TEXT,
    created_at  TEXT DEFAULT (datetime('now')),
    updated_at  TEXT DEFAULT (datetime('now'))
);
```

### 1.3 旧数据一次性迁移（`migrate_schema()` 在 `init_db` 内调用）
- `item_type` 为空的历史行按 `source_type` 补全：`web_clip→website`、`upload→file`、`note→note`、`task_doc→file`。
- `rich_body` 为空的旧行：用 `<p>` 包裹 `content`（转义后）填入，保证旧笔记走统一的富文本渲染路径。
- `title_pinyin` 为空的历史行：用 pypinyin 补算（未装 pypinyin 时回退为 `title`）。
- 新增列已存在则跳过（`PRAGMA table_info` 探测），可重复执行。

## 2. 接口契约（沿用 `/api/knowledge` 前缀）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/knowledge` | 列表 / 搜索。新增参数：`item_type`、`package_id`、`include_descendants=1`、`time_range=today\|week\|month`、`group_by=none\|title\|time`、`q`（FTS）。无新参数时行为与原版一致（向后兼容） |
| POST | `/api/knowledge/notes` | 建笔记。**兼容旧调用**：可只传 `{content,title}`（纯文本）；也可传 `{title, item_type, rich_body(HTML), url, package_id}` 走富文本。rich_body 入库前 `nh3` 净化，`content` 同步写纯文本 |
| GET | `/api/knowledge/packages` | 包扁平列表（带 parent_id），前端递归构树 |
| POST | `/api/knowledge/packages` | 新建包 `{name, parent_id?, color?, sort_order?}` |
| PATCH | `/api/knowledge/packages/{id}` | 改名/改色/移动（校验不能移到自己子孙下） |
| DELETE | `/api/knowledge/packages/{id}` | 删包；子资料 `package_id` 置 NULL 回未归档，子包变顶层 |
| PATCH | `/api/knowledge/{id}` | 更新 `title/rich_body/item_type/url/package_id` |
| DELETE | `/api/knowledge/{id}` | 删资料（原接口复用） |
| GET | `/api/knowledge/{id}` | 详情（原接口复用，现含 rich_body 等字段） |

**列表返回结构**
- `group_by=none`：`{mode:"list", cards:[...]}`
- `group_by=title`：`{mode:"group", groups:[{group:"A", items:[...]}, ...]}`，组按拼音首字母、`items` 组内按拼音排
- `group_by=time`：`{mode:"group", groups:[{group:"今天"|"本周"|"本月"|"更早", items:[...]}]}`
- `q` 命中时始终是搜索模式：`{mode:"search", results:[...]}`

**时间区间（UTC，与存储一致）**：`today`=`00:00 UTC 至今`、`week`=本周一 `00:00 UTC 至今`、`month`=本月 1 号 `00:00 UTC 至今`。

## 3. 后端关键实现点

1. **入库单一入口 `ingest_card()` 已是全局入口**（AI "记一下"、剪藏、上传、手动笔记都走它）。
   结构化笔记创建时：
   - 有 `rich_body` → `nh3.clean()` 净化（白名单 `h1,h2,p,br,strong,em,ul,ol,li,a`；`a` 仅放行 `href`）→ 存 `rich_body`；`content` = 净化后 HTML 去标签的纯文本。
   - 只有纯 `content` → `content` 原样存，`rich_body` 留空（迁移/展示层回退）。
   - `title_pinyin` = pypinyin(`title`)。
2. **FTS 不变**：`upsert_search("knowledge_card", cid, title, content)` 仍索引 `content`（纯文本），所以标题/正文搜索照常命中，包括富文本里的标题文字（因为 content 已含其纯文本）。
3. **包树防环**：移动包时递归收集目标包的所有子孙 id，禁止把 `parent_id` 设为自身或子孙。
4. **删除包**：依赖 `ON DELETE SET NULL`，无需手写级联。

## 4. 前端关键实现点

- 依赖：`@tiptap/react` + `@tiptap/starter-kit`（StarterKit 已含 H1/H2/段落/加粗/斜体/有序无序列表）。OnlyOffice 仍只用于 .docx/.xlsx，不与笔记编辑器混用。
- 新增 `NoteEditor.tsx`：TipTap 工具栏（H1/H2/正文/加粗/列表），`editor.getHTML()` 拿 HTML 提交；只读展示用 `dangerouslySetInnerHTML` 渲染**已净化的** `rich_body`。
- `KnowledgePage.tsx`：左侧包树（可折叠/选择过滤）、顶部筛选栏（类型/包/时间/分组切换 + 搜索）、笔记卡片支持富文本渲染与富文本编辑入口。
- `client.ts`：扩展 `knowledge` 对象，新增 `packages` CRUD、列表新参数、结构化 `createNote`/`update`。

## 6. 与原方案的主要偏离（请知悉）

1. 接口用 `/api/knowledge` 而非 `/api/notes` —— 不新建平行路由，前端已对接前者。
2. 不引入 `file_ref`，文件指针复用 `source_id`。
3. 时间区间按 UTC 算（因存储即 UTC），而非"后端本地时间"。
4. 拼音分组依赖 `title_pinyin` 列 + pypinyin，而非 SQLite 默认排序。
5. `task_doc` 明确映射为 `file` 型。
