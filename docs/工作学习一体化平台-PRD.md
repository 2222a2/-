# 工作学习一体化平台 · 产品需求文档（PRD）

**版本**：v0.2（方案分析稿 · 含范围红线）
**日期**：2026-10-14
**状态**：待评审
**作者**：郭郭（产品 / 全栈）、小渝（陪跑）

---

## 1. 产品概述

### 1.1 背景与问题
工作 / 学习人群日常在多个软件间反复横跳：用备忘录或 Todo 记任务、用 Word/PPT/Excel 产出、用豆包等 AI 生成内容、用日历排期、用笔记存资料。每次"想做一件事"都要切换 N 个工具、反复找资料，上下文丢失、记录散落，周报月报还要手动拼。

### 1.2 产品定位
一个**单一空间的工作操作系统**：让用户在一个标签页里完成「想清楚 → 拆解成步骤 → 用文档 / 表格 / PPT 做出来 → 自动留下工作记录 → 顺手把学习和奖励也管了」，不用来回切软件、到处找资料。

### 1.3 目标用户
- **工作人群**：实习生 / 职场新人 / 个人项目管理（管任务、出周报月报、写文档）。
- **学习人群**：备考 / 自学用户（按课本和空闲时间排学习计划、打卡、复盘）。
- 本质是"同一个人"的两个身份切换，而非两类孤立用户。

### 1.4 核心价值主张
**零跳转**：做一件事所需的需求澄清、步骤、文档、资料、记录、汇报，全在同一个空间内闭环。

### 1.5 与竞品差异
| 维度 | 本平台 | Notion / 飞书 | Office | 纯 AI 工具 |
|---|---|---|---|---|
| 任务 → 文档 → 报告 自动串联 | 原生 | 弱 | 无 | 无 |
| AI 自动拆解 + 追问分析 | 原生 | 无 | 无 | 部分 |
| 学习计划联动任务系统 | 原生 | 无 | 无 | 无 |
| 文档三件套内嵌可生成 | 集成 | 文档弱 / 演示弱 | 强但孤立 | 生成不编辑 |
| 本地优先 / 隐私 | 支持 | 云端 | 本地 | 云端 |

## 2. 范围红线与分期（v0.2 新增，防范围膨胀）

### 2.1 铁律
> 任何功能，先问一句——"它直接减少一次软件切换 / 一次找资料吗？"回答不上来，就进延后池。

产品灵魂是"零跳转"。所有"增强体验但非直接贡献"的能力（仪表盘、自动化市场、AI 记忆、OKR……）都有价值，但**不是现在**。用这条铁律当筛子，把膨胀关进笼子。

### 2.2 四档分层
- **A 不可削减核心 · Phase 1**：用户原始的工作闭环。砍掉任一，"零跳转"立不成立。
- **B 原始第二支柱 · Phase 2**：学习计划 + 奖励视频，用户点名要的，但可晚于工作闭环。
- **C 延后池 · Phase 3+**：有用但非零跳转直接贡献，等核心稳了再补。
- **D 砍掉 / 缓做（红线以下）**：现在做是 distraction，需要时再长出来。

### 2.3 收口决策（2026-10-14 确认）
- **Phase 1 = A 档工作闭环 5 件套 + M7 时间轴/专注模式**。专注计时直接把工时喂给周报，是"零跳转"的执行端，值得往前拉。
- B / C / D 严格按档位延后，不提前。

## 3. 目标与非目标

- **In scope**：任务管理、任务分析引擎、AI 文件生成、文档中心（OnlyOffice 集成）、自动周报月报、时间轴/专注模式（Phase 1）；学习计划、奖励与成就复盘视频（Phase 2）。
- **C 档延后（Phase 3+）**：资料库 RAG 之外的增强（情境感知聚合、复盘中心、仪表盘、自动化/工作流市场、AI 长期记忆、同步/隐私开关、PWA、Inbox 收集箱）。
- **D 档砍掉/缓做**：OKR 战略层（单人起步过早抽象）、成就墙/连胜动画等锦上添花。
- **Out of scope（暂不做）**：多人实时协作团队版、跨企业权限体系、移动端 App（先做 Web 本地）、商业化计费。

## 4. 功能需求（含 Phase 归属）

优先级标记 `[Px·PhaseN]`：P = 重要度（P0 必须 / P1 近期 / P2 远期），PhaseN = 上线档位（见第 2、8 节）。

### M0 资料聚合底座（贯穿 / Phase 1）
- [P0·P1] 全局搜索：跨任务、文档、对话、资料库检索（SQLite FTS5）。
- [P0·P1] 网页剪藏：浏览器插件 / 书签页把网页存为资料卡片。
- [P0·P1] 统一命令面板（Cmd/Ctrl+K）：一句话触发建任务 / 生成文档 / 查资料。
- [P0·P1] 日历 / 提醒中心：所有 deadlines 统一视图 + 临近提醒。
- [P0·P1] 资料库 RAG：资料卡片向量化，供 AI 检索上下文（"不用找资料"的底层支撑）。
- [P1·P3] 情境感知：做某任务时右侧自动聚合"相关资料 / 历史对话 / 模板"。

### M1 文档中心（Word / PPT / Excel · Phase 1 为主）
- [P0·P1] OnlyOffice 嵌入：站内打开 / 编辑 docx/xlsx/pptx。
- [P0·P1] AI 生成文件：豆包产出结构化内容 → 后端渲染成真实 Office 文件 → OnlyOffice 打开。
- [P1·P1] 版本管理：自动存版本，可回滚、可导出。
- [P1·P2] PPT 模板库：按场景（汇报 / 教学 / 复盘）筛选模板，AI 填充。
- [P2·P2] 文档与任务绑定：任务完成即文档定稿。

### M2 AI 助手层（可插拔 · Phase 1）
- [P0·P1] LLMProvider 抽象：豆包默认，预留通义 / GLM / 本地 Ollama。
- [P0·P1] Function Calling：AI 可建任务、写文档、查资料、拉数据。
- [P1·P1] 资料 RAG 检索作为对话上下文。
- [P2·P3] 多 Agent 编排（复杂任务分解给子 Agent）。

### M3 任务管理 + 自动报告（Phase 1 为主）
- [P0·P1] 任务 CRUD：标题、截止时间、完成度（子任务汇总）、紧急程度。
- [P0·P1] 四象限优先级（重要 / 紧急），颜色区分。
- [P0·P1] 自动周报：聚合本周完成任务 → 草稿 → 可改 → 导出 Word/PDF。
- [P1·P1] 长期未动任务提醒（防空洞）。
- [P1·P2] 自动月报 + 一键推送（给自己 / 上级）。
- [P2·P3] 工时报表（基于 M7 专注计时数据）。

### M4 任务分析引擎（核心亮点 · Phase 1）
- [P0·P1] 需求澄清：AI 反问目标 / 交付物 / 截止 / 限制。
- [P0·P1] 需求确认卡：一段话复述，用户拍板。
- [P0·P1] 步骤拆解 + 工期估算（依赖、所需资料 / 工具）。
- [P0·P1] 计划清单：可勾选、可排期，直接写入任务管理。
- [P1·P1] 逐步追问 → 每步「风险 / 卡点 / 前置条件」三问 → 沉淀"问题预案"。
- [P1·P2] 同类任务模板复用。
- [P2·P3] 导出"执行手册"。

### M5 学习计划（Phase 2）
- [P0·P2] 课本入库：上传 PDF / 图片 → 解析目录章节 → 拆学习单元。
- [P0·P2] 排课：可用时间段 + 优先级 → 日 / 周 / 月计划（月可选）。
- [P1·P2] 遗忘曲线复习：艾宾浩斯自动插复习节点。
- [P1·P2] 进度可视化：日历热力图、连续打卡。
- [P2·P3] 复杂单元用 M4 拆学习步骤。

### M6 奖励系统（Phase 2）
- [P0·P2] 积分 / 徽章 / 连续打卡。
- [P0·P2] 成就复盘视频：完成事项 → 带字幕音乐短片。
- [P1·P3] 轻量 gamification（休息卡 / 皮肤等兑换）。
- [P2·P3] 社交分享卡片。

### M7 时间轴与专注模式（Phase 1 · 收口时新增）
- [P0·P1] 时间轴：任务 / 学习计划拖入日历时间块，统一调度视图。
- [P0·P1] 专注模式：开始任务 → 计时 + 屏蔽干扰 → 工时自动喂给 M3 周报（"零跳转"执行端）。
- [P1·P1] 与 M3 完成度 / 日历联动，冲突检测。

### C 档延后池（Phase 3+，列出不展开）
复盘中心（AI 引导反思）/ 个人仪表盘（趋势图）/ 自动化·工作流市场（固定套路一键跑）/ AI 长期记忆·用户画像 / 端到端同步与隐私开关 / PWA 形态 / Inbox 收集箱。

### D 档砍掉 / 缓做（红线以下，不排期）
OKR 战略层（单人起步过早抽象）/ 成就墙·连胜动画等锦上添花。

## 5. 关键用户流程（端到端）

**场景 A（工作闭环 · Phase 1 验收）**：命令面板"准备周五客户周报" → M4 澄清需求 → 生成步骤清单写入 M3（截止 / 紧急 / 完成度）→ M2 调豆包生成 Word 草稿（python-docx）→ M1 OnlyOffice 编辑定稿 → 标记完成 → M7 专注计时已自动累计工时 → 自动进周报汇总。

**场景 B（学习闭环 · Phase 2 验收）**：上传课本 PDF → M5 解析拆单元 → 按空闲时间排周计划 → 每日打卡 → 到期复习提醒 → 阶段完成触发 M6 复盘视频。

---

## 6. 非功能性需求
- **本地优先**：数据存本地，离线可用；OnlyOffice 本地 Docker。
- **隐私**：资料不出本机（本地模型可选）。
- **性能**：命令面板响应 < 200ms；报告生成 < 5s。
- **可扩展**：AI Provider、文档模板、学习计划算法、范围档位均可插拔。

## 7. 技术架构与选型

### 7.1 总体架构
```
前端(React+TS)  ←→  后端(FastAPI)  ←→  [OnlyOffice Docs(Docker) | LLM Provider 抽象 | 本地 SQLite | 文件目录]
                                          AI 层横切：Function Calling 调后端能力；RAG 接资料库
```

### 7.2 技术栈
- 前端：React + TS + zustand + @onlyoffice/document-editor-react
- 后端：FastAPI + SQLite
- AI：LLMProvider（doubao / tongyi / glm / ollama）+ function calling；RAG 复用 chromadb + sentence-transformers
- 文档生成：python-docx / python-pptx / openpyxl
- 视频：moviepy（后端合成）或前端 canvas + 录屏
- 本地协同：OnlyOffice 自带

### 7.3 数据模型（核心表）
- `Task`(id, title, deadline, urgency, importance, status, completion%, parent_id)
- `PlanAnalysis`(task_id, requirement, steps[], qa_log[])
- `Doc`(path, type, linked_task_id, versions[])
- `StudyPlan`(textbook_id, granularity, slots[])
- `FocusSession`(task_id, start, end, duration)  -- M7 专注计时
- `Report`(type, period, content, auto_generated)
- `Reward`(points, badges[], videos[])

## 8. 分期路线图（按红线收口）

- **Phase 1 · MVP 工作闭环 + 专注（A + M7）**：M0(命令面板/搜索/剪藏/日历/RAG) + M1(AI 生成+OnlyOffice) + M2(豆包+Function Calling) + M3(任务+自动周报) + M4(分析四段式) + M7(时间轴/专注)。**验收：场景 A 跑通，且专注计时自动进周报。**
- **Phase 2 · 第二支柱（B）**：M5 学习计划（课本 + 日周）+ M6 奖励 / 成就复盘视频。**验收：场景 B 跑通。**
- **Phase 3 · 黏性规模化（C 档）**：复盘中心 / 仪表盘 / 自动化市场 / AI 记忆 / 同步 / PWA / Inbox。
- **红线以下（D 档）**：OKR / 成就墙动画，不排期，需要时再长。

## 9. 风险与待决
- OnlyOffice Docker 资源占用（本地机器性能）。
- 本地模型能力边界（复杂拆解可能需云端模型）。
- 课本 PDF 解析准确率（OCR / 版式）。
- 复盘视频观感需调模板。
- 编辑器集成 OnlyOffice 的授权与部署复杂度（Community 版 AGPL）。
- **范围膨胀风险**：任何新需求先过第 2 节铁律，否则进 C/D 档。

---

## 10. 成功度量
- Phase 1：用户连续 2 周用本平台完成周报；任务分析使用率 > 50%；专注计时周活 > 60%。
- Phase 2：学习计划完成率、连续打卡天数。
- Phase 3：复盘 / 仪表盘日活，自动化工作流复用次数。

---

## 11. 术语表
- **零跳转**：不切换软件 / 标签页完成一件事。
- **需求确认卡**：AI 复述需求供用户拍板。
- **问题预案**：逐步追问沉淀的该步骤风险 / 卡点。
- **成就复盘视频**：把一段时间完成事项剪成的带字幕音乐短片。
- **范围红线**：第 2 节铁律与四档分层，用于止住范围膨胀。
