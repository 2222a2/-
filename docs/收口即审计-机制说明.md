# 收口即审计 · 机制说明

> 配套脚本：`scripts/audit_consistency.py`
> 目的：把"每个 Phase 收口跑一次一致性审查"固化成**可重复、可门槛化**的机制，防止再出现"代码已落地、文档没记录"的漏记。

---

## 1. 背景

2026-10-19 盘点发现：M0 笔记子系统的 **TipTap（前端富文本）+ nh3（后端 HTML 净化）** 早已随实现引入，但《Phase1 技术实现设计》《一致性审计表》《README》三处"技术栈单一事实来源"全都没记——这是审计自身的覆盖盲区。为根治，建立"收口即审计"机制：每次 Phase 收口自动对账，结论入 `docs/`。

---

## 2. 触发时机

- 每个 **Phase 验收 / 收口**时（如 Phase 1 收口、Phase 2 M5 收尾）。
- 任何 **新增依赖 / 改端口 / 换存储 / 改 AI 后端** 的合并后。
- 发现线上或复跑走查脚本踩坑时，立即补跑。
- 建议频率：不短于每个 Phase 一次。

---

## 3. 责任人

- 开发（郭郭）收口前自跑；小渝（AI）可代为生成报告。

---

## 4. 四维度检查清单

| 维度 | 检查项 | 失败含义 |
|---|---|---|
| 端口 | 后端默认 8000、Vite 代理 8000、OO 8080、verify 脚本 BASE_URL 统一、无历史 8021 残留 | 端口分裂导致起服后脚本连不上 |
| venv | 仅一个虚拟环境、README 指向的 venv 真实存在、requirements.txt 存在 | 双 venv 残留 / 指向损坏环境 |
| 依赖 | 关键依赖均记入三处单一事实来源（SoT）、requirements 依赖有代码引用、前端 deps 有引用 | 漏记技术栈 / 僵尸依赖 |
| 落库口径 | 单一 SQLite(app.db)、无第二 DB 引擎、FTS5 已建、报告落 report 表、报告聚合含文档维度 | 存储口径漂移 / 报告不落库 |

---

## 5. 执行

```bash
cd worklearn-platform
python scripts/audit_consistency.py                  # 用今天日期
python scripts/audit_consistency.py --date 2026-10-19
```

- 需要 Python 3.10+，仅用标准库，**无需激活 venv**。
- 输出：`docs/一致性审查-YYYY-MM-DD-收口审计.md` + 终端摘要。
- 任何 **FAIL → 退出码 1**，可作为收口门槛（人工 gate；若上 CI 则直接拦合并）。

---

## 6. 与 `verify_*.py` 的区别

| 脚本 | 性质 | 说明 |
|---|---|---|
| `scripts/verify_*.py` | 功能 / 行为验收 | 起服务跑端到端断言（如报告导出、周报聚合、防空洞提醒） |
| `scripts/audit_consistency.py` | 架构 / 文档一致性审计 | 静态对账（端口 / venv / 依赖 / 落库口径），**不跑服务** |

两者互补：verify 证"功能对"，audit 证"说法与代码一致"。

---

## 7. 闭环（必须清零 / 记录在案才算收口）

- **FAIL** = 工程卫生债（P0），必须修复后才算收口（如双 venv、端口分裂）。
- **WARN（SoT 漏记）** = 必须补进三处单一事实来源（Phase1 技术设计 / 一致性审计表 / README 技术栈段），补完重跑直到 WARN 清零。
- **WARN（僵尸依赖）** = 确认后清理 requirements / package.json。

> 经验法则：新增一个依赖，要动**三处**文档（技术设计、审计表、README 技术栈段）+ 跑一次 `audit_consistency.py` 确认无 SoT 漏记 WARN。

## 8. 接入 git pre-commit（每次提交自动拦 FAIL）

> 已落地（2026-10-19）。提交时若审计存在 FAIL，提交被直接阻断；PASS 才放行。

### 原理

- 钩子本体（可跟踪、团队共享）：`scripts/git-hooks/pre-commit`
- 安装动作（仅本地生效，不进仓库）：拷贝到 `.git/hooks/pre-commit` 并赋予可执行权限。
- 钩子逻辑：探测 python 解释器 → 调用 `audit_consistency.py --no-report` → 退出码非 0 即 `exit 1` 阻断提交。
- `--no-report`：pre-commit 场景下**只校验不落盘**，避免每次提交都在 `docs/` 多一份报告文件。手动收口盘点时仍用不带 `--no-report` 的命令生成报告。

### 安装（每个克隆只需一次）

- **Windows**：双击 `scripts/install-hooks.bat`，或 `cmd` 里跑它。
- **macOS / Linux**：`bash scripts/install-hooks.sh`。
- 脚本会顺手清理一个**曾经被误设**的 `core.hooksPath`（本机曾指向一个 python 文件路径，导致所有 hook 失效）；清理后 git 回退到默认 `.git/hooks` 目录，钩子才会生效。

### 逃生口

- 临时跳过本次审计：`SKIP_CONSISTENCY_AUDIT=1 git commit ...`
- 跳过所有 hooks（含本钩子）：`git commit --no-verify`
- 仅建议紧急情况下使用，跳过后应补跑 `python scripts/audit_consistency.py` 确认无 FAIL。

### 团队复用说明

`.git/hooks/` 不会被 git 跟踪，所以新成员 clone 后需各自跑一次安装脚本。新人 onboarding 清单加一条："clone 后运行 `scripts/install-hooks.bat`（Win）/ `bash scripts/install-hooks.sh`（Mac/Linux）"。
