# M5 遗忘曲线复习 · 实现方案

> 基于 2026-10-16 代码核实：`study_task` 表 + `study_tasks.py` 路由已就位（批量建/列/改/删 + 周进度聚合），缺的是"学完自动插复习节点"的算法与可视化。本方案只补算法与最小 schema 改动，**不新建表、不引入推送服务**（本地应用现实），符合"轻量、不膨胀"的红线。

## 0. 一句话逻辑

用户在「学习页」把某个学习任务勾成 `done=1`（= "这个单元我学完了"）→ 系统立刻以该任务的学习日为基准，**自动生成 1/2/4/7/15 天后的 5 条"复习"任务** → 之后每天打开学习页，今天到期的复习任务被高亮置顶提醒。复习任务本身被勾掉只算"打卡"，**不再连锁生成**（避免指数爆炸）。

## 1. 最小改动清单（动哪些文件）

| 文件 | 改什么 |
|---|---|
| `backend/app/db.py` | ① `study_task` 建表补 3 列；② 新增 `spawn_reviews_for_task()` + `list_due_reviews()`；③ `patch_study_task` 返回旧 done（或新增小查询） |

## 2. 数据模型变更（复用原表，加 3 列）

不加新表——复习任务本质还是"某天要做的一件事"，复用 `study_task` 最省事，用 `source='review'` 区分；新增 3 列记录血缘与轮次：

```sql
-- db.py 的 CREATE TABLE study_task 直接补这 3 列（新库即含），老库用 ALTER：
ALTER TABLE study_task ADD COLUMN review_of   INTEGER DEFAULT NULL; -- 指向原始新学任务 id；新学任务为 NULL
ALTER TABLE study_task ADD COLUMN review_stage INTEGER DEFAULT NULL; -- 1..5，对应第几轮复习
ALTER TABLE study_task ADD COLUMN due_offset  INTEGER DEFAULT NULL; -- 1/2/4/7/15，相对学习日的天数偏移
```

含义示例：原任务「10-16 学完 高数·极限」→ 生成 5 条：
`(date=10-17, title="复习：高数·极限", source='review', review_of=<原id>, review_stage=1, due_offset=1)` … 一直到 `due_offset=15`。

## 3. 核心算法（放 `db.py`）

```python
# ---------- 备考学习任务（study_task）----------

REVIEW_OFFSETS = [1, 2, 4, 7, 15]  # 艾宾浩斯经验节点，可调


def spawn_reviews_for_task(task_id: int) -> int:
    """原始新学任务被标记完成时，生成 1/2/4/7/15 天后的复习任务。

    返回生成条数。幂等：先按 review_of 清掉该任务已有的复习任务再插，
    重复勾选也不会出现重复节点。
    """
    conn = get_conn()
    row = conn.execute(
        "SELECT id, date, period, subject, title FROM study_task "
        "WHERE id=? AND review_of IS NULL",  # 只认"原始新学任务"，复习任务自己不会触发
        (task_id,),
    ).fetchone()
    if not row:
        conn.close()
        return 0
    base_date = row["date"]
    today = datetime.now().strftime("%Y-%m-%d")

    # 幂等清空
    conn.execute(
        "DELETE FROM study_task WHERE source='review' AND review_of=?",
        (task_id,),
    )

    count = 0
    for stage, offset in enumerate(REVIEW_OFFSETS, start=1):
        due = (datetime.strptime(base_date, "%Y-%m-%d") + timedelta(days=offset)).strftime("%Y-%m-%d")
        if due < today:
            continue  # 理论不会发生（offset>=1），保险跳过过去日期
        conn.execute(
            """INSERT INTO study_task
               (date, period, subject, title, done, source, sort_order,
                review_of, review_stage, due_offset)
               VALUES (?,?,?,?,0,'review',0,?,?,?)""",
            (due, row["period"], row["subject"],
             f"复习：{row['title']}", task_id, stage, offset),
        )
        count += 1
    conn.commit()
    conn.close()
    return count


def list_due_reviews(date_str: str) -> list[dict]:
    """返回某天到期且未完成的复习任务（供前端"今日待复习"卡片）。"""
    conn = get_conn()
    rows = conn.execute(
        "SELECT * FROM study_task WHERE date=? AND source='review' AND done=0 "
        "ORDER BY review_stage",
        (date_str,),
    ).fetchall()
    conn.close()
    return [dict(r) for r in rows]
```

### 为什么这样设计（关键决策）

- **触发点选 PATCH `done 0→1` 而非"新建时"**：复习节点必须基于"实际学完的那天"，而不是"计划排的那天"。排了没学 = 不该有复习；学完了才插，符合艾宾浩斯"以学习时刻为 0 点"。
- **幂等 DELETE 再插**：用户可能反复勾/取消，`review_of` 清空重插保证永远正好 5 条，不脏数据。
- **复习任务 `done=1` 不连锁**：只在 `review_of IS NULL` 的原始任务上触发，复习的复习不再生新复习——否则 15 天后还会再爆 5 条，失控。5 个固定节点已覆盖遗忘临界点，足够。
- **复用 `period/subject`**：复习尽量排回原时间段（如原来晚上学，复习也排晚上），符合用户作息惯性；原表无时段冲突校验，简单沿用即可。

## 4. 路由改动（`study_tasks.py`）

```python
@router.patch("/{task_id}", response_model=dict)
def patch_study_task(task_id: int, done: int | None = None, title: str | None = None):
    if done is None and title is None:
        raise HTTPException(status_code=400, detail="nothing to update")
    before = db.get_study_task_done(task_id)          # 新增小查询：取旧 done
    db.patch_study_task(task_id, done=done, title=title)
    if done == 1 and before == 0:                      # 仅在"新完成"瞬间触发
        n = db.spawn_reviews_for_task(task_id)
        return {"ok": True, "id": task_id, "reviews_spawned": n}
    return {"ok": True, "id": task_id}


@router.get("/reviews/due", response_model=list[schemas.StudyTaskOut])
def due_reviews(date: str | None = None):
    """今日（或指定 date）到期未做的复习任务。"""
    base = date or datetime.now().strftime("%Y-%m-%d")
    return db.list_due_reviews(base)
```

`db.get_study_task_done` 只需一行：`SELECT done FROM study_task WHERE id=?`。

## 5. 前端改动（`StudyTasksPage.tsx`）

1. **顶部"今日待复习"卡片**：页面加载时调 `GET /api/study-tasks/reviews/due`，列出 `title` + `review_stage`（第几轮）+ `due_offset`（第几天），未做的高亮、做了置灰。勾选复用现有 PATCH。
2. **列表标记**：`source==='review'` 的任务加"复习"小标签 / 不同底色，与"新学"区分（不用 emoji，用文字 chip）。
3. **热力图 / 连续打卡天然复用**：`weekly_progress` 按 `done` 聚合，复习任务被勾掉同样计入当日完成，无需额外改动——这是复用原表带来的免费好处。

## 6. 边界与风险

- **`auto` 任务被生成器重置**：`upsert_study_tasks_for_date` 每天只删 `source='auto'` 的，复习任务 `source='review'` 不受影响；且复习节点在 `done 0→1` 那一刻已独立落库，原任务后续被重置/重建不影响已生成的复习。
- **`review_of` 悬空**：若原 `auto` 任务被删后重建（id 变），`review_of` 指向旧 id。但复习任务只展示自己、`title` 已固化，悬空无功能影响，可接受（如需严谨可加软校验，暂不值得）。
- **跨周/跨月**：`due` 日期正常落在未来任意月，现有周区间 `GET` 与 `list_due_reviews` 都能查到。
- **重复勾选**：幂等清空保底，永远 5 条。

## 7. 验收口径

1. 建/选一个任务 → PATCH `done=1` → 响应含 `"reviews_spawned": 5`（若都在未来）。
2. 查该任务未来 1/2/4/7/15 天，各出现 1 条 `source='review'`、`review_of` 指向原 id、`title` 以"复习："开头。
3. 再次 PATCH（取消再勾）→ 对应日期仍只有 5 条，不翻倍。
4. `GET /api/study-tasks/reviews/due?date=<明天>` → 返回明天到期的复习任务。
5. 复习任务勾掉后，周进度热力图当日完成数 +1。
