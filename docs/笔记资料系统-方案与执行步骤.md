# 笔记 / 资料管理系统 — 整体方案与可执行步骤

> 目标：在现有「工作学习一体化平台」(worklearn-platform) 之上，补一套可用的笔记/资料管理：
> 标题 + 富文本正文(H1/H2/段落) + 类型分类(笔记/网站/文件) + 筛选/分组(类型/时间/标题) + 包(容器) 收纳。

---

## 一、需求拆解（你的口语 → 功能点）

1. **笔记结构**：标题(必填) + 正文；正文支持 H1 / H2 / 正文(段落) 等格式。
2. **资料类型分类**：笔记(note) / 网站(website) / 文件(file)，可扩展（"等"）。
3. **筛选**：按类型、按时间、按标题 过滤。
4. **分组视图**：按标题(拼音/A-Z) 或 按时间(今天/本周/本月) 分组展示。
5. **容器「包」**：可创建包(package/folder)，包内可新建 笔记/网站/文件；包本身可再归类。
6. **(隐含) 搜索**：复用已有 FTS5 全文检索，富文本正文也要能被搜到。

## 二、与现有平台的关系（核心判断）

你已有的平台在 `C:\Users\用户\worklearn-platform`，其中 **M0 资料聚合底座** 已经具备：

## 三、数据模型设计（SQLite，扩展现有 `app.db`）

### 新增表 `note_package`（包 / 文件夹）

```sql
CREATE TABLE IF NOT EXISTS note_package (
    id         INTEGER PRIMARY KEY AUTOINCREMENT,
    name       TEXT NOT NULL,
    parent_id  INTEGER REFERENCES note_package(id) ON DELETE SET NULL, -- 包里套包（已确认支持多层）
    sort_order INTEGER DEFAULT 0,
    color      TEXT,                      -- 侧边栏配色，可选
    created_at TEXT DEFAULT (datetime('now')),
    updated_at TEXT DEFAULT (datetime('now'))
);
```

> **包多层嵌套（已确认支持）**：`parent_id` 自引用即为此预留。前端渲染递归树；移动资料/子包时改 `parent_id`；删包时子包 `parent_id` 置 NULL（不级联删，避免误删）。

### 扩展现有 `knowledge_card`（向后兼容，ALTER 加列）

```sql
ALTER TABLE knowledge_card ADD COLUMN package_id INTEGER REFERENCES note_package(id) ON DELETE SET NULL;
ALTER TABLE knowledge_card ADD COLUMN item_type  TEXT;   -- note | website | file（统一筛选维度）
ALTER TABLE knowledge_card ADD COLUMN rich_body TEXT;   -- 富文本 HTML（笔记用；网站/文件可存摘要）
ALTER TABLE knowledge_card ADD COLUMN url       TEXT;   -- website 用
ALTER TABLE knowledge_card ADD COLUMN file_ref  TEXT;   -- file 用，指向 M0 上传文件

CREATE INDEX IF NOT EXISTS idx_card_package ON knowledge_card(package_id);
CREATE INDEX IF NOT EXISTS idx_card_itemtype ON knowledge_card(item_type);
CREATE INDEX IF NOT EXISTS idx_card_created ON knowledge_card(created_at);
```

> 说明：
> - `item_type` 与现有 `source_type` 并存过渡；新接口统一用 `item_type` 做筛选。旧数据(web_clip→website, upload→file, note→note, task_doc→file/note) 用一次性脚本映射进 `item_type`。
> - 富文本正文存 **HTML**，入库前后端用 `nh3` 净化防 XSS；纯文本副本同步进 `search_index.body`，搜索照样命中。
> - `package_id` 允许 NULL = 未归档/根目录。

## 四、富文本编辑器选型（H1/H2/正文）

前端 React，三选一（**推荐 TipTap**）：

| 方案 | 优点 | 缺点 |
|------|------|------|
| **TipTap（推荐）** | 基于 ProseMirror，原生 H1/H2/段落/加粗/列表；输出 HTML；React 契合好、可扩展 | 需装 `@tiptap/*` 一组包 |
| Quill | 开箱即用 toolbar，集成快 | 自定义块级格式略弱，HTML 输出需后处理 |
| Markdown 编辑器 | 轻量，`#`/`##` 即时渲染 | "设置字体格式"交互不如所见即所得直观 |

**存储约定**：正文存 HTML；渲染用 TipTap 只读模式或受控 `dangerouslySetInnerHTML`（仅渲染已净化的内容）。

## 五、前端界面结构

- **左侧栏（导航 + 筛选）**
  - 包树：列出所有包（可折叠、可新建包）；点包 → 筛选该包内资料。
  - 类型筛选：`全部 / 笔记 / 网站 / 文件`。
  - 时间筛选：`全部 / 今天 / 本周 / 本月 / 自定义`。
- **中间（列表 / 分组区）**
  - 顶部：搜索框（复用 FTS5）+ 「新建」下拉（新建笔记/网站/文件）。
  - 列表支持两种分组切换：① 按标题(拼音/A-Z) ② 按时间(今天/本周/本月)。
  - 卡片：标题 + 类型标签 + 所属包 + 更新时间 + 摘要。
- **右侧（编辑 / 详情区）**
  - 标题输入框（置顶，必填）。
  - 富文本编辑器（H1/H2/正文 toolbar）。
  - 网站：额外 url 字段；文件：上传/选择；包：下拉选归属。
  - 保存：自动保存(debounce 1.5s) + 手动保存；保存后同步 FTS5。

## 六、后端接口（加在现有 FastAPI，复用 db / schemas / search）

| 方法 | 路径 | 作用 |
|------|------|------|
| GET | `/api/notes/packages` | 包树列表 |
| POST | `/api/notes/packages` | 新建包 |
| PATCH | `/api/notes/packages/{id}` | 改名/改色 |
| DELETE | `/api/notes/packages/{id}` | 删包（子项 package_id 置 NULL） |
| GET | `/api/notes?package_id=&type=&group_by=title\|time&q=` | 列表 + 筛选 + 分组 |
| POST | `/api/notes` | 新建（type/title/rich_body/url/file_ref/package_id） |
| GET/PATCH/DELETE | `/api/notes/{id}` | 详情 / 改 / 删 |

- 复用 `ingest_card` 落库后同步 FTS5；`rich_body` 净化后入库。
- 删除走 `delete_knowledge_card` 清理索引 + 向量库（已有）。

## 八、关键技术坑（来自你已有项目，直接复用经验）

- **IPv6**：vite `host:'127.0.0.1'`，代理 target `127.0.0.1`（否则 IPv4 连不上）。
- **safe-delete**：vite 启动前先把 `node_modules/.vite` **改名**再起（回收站不可用导致删除被拦截）。
- **富文本 XSS**：必须后端 `nh3` 净化；前端不要裸 `innerHTML` 未净化内容。
- **端口占用**：uvicorn 8000 / vite 5173；占用用 `taskkill /F /PID` 杀。
- **中文短词搜索**：沿用 FTS5 trigram + `LIKE` 兜底（<3 字符也能搜到）。
